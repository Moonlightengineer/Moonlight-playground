# Hello, World｜30 秒純程式短片

一段 30 秒、1920×1080、24 fps 嘅短片。**冇攝影機、冇拍攝素材、冇 AI 影片生成器、冇現成 3D 模型或音效庫**——每一格畫面、每一個音，都係由呢個資料夾入面嘅程式碼逐格計算出嚟。全部程式由 Claude（Anthropic 開發嘅 AI）喺一次對話入面寫成、渲染同檢查。

- 觀看：`index.html`（影片＋即時運算版＋拆解模式）
- 影片檔：`film.mp4`
- 唯一外來檔案：標題用嘅三個開源字型子集（`fonts/`，SIL Open Font License）

## 一句講晒

片中四行程式碼就係劇本；城市就係由呢四行字「起」出嚟；游標升上天變成月亮；最後城市自己印出 `hello, world`。

## 分鏡（全片只有兩個鏡頭）

| 時間 | 程式碼（片底字幕） | 畫面 | 聲音 |
|---|---|---|---|
| 0–5 秒 | （打緊字） | 黑色「螢幕」上，發光點陣字一個個 token 咁出現，鏡頭慢慢拉遠 | 每個 token 一粒鐘琴音、一下鍵盤聲，按字嘅位置左右聲道 |
| 5–7.5 秒 | `city = build(code);` | 每一點字升起變成大廈，鏡頭由頭頂俯衝落城市 | 低頻隆隆聲、銅管式「braam」 |
| 7.5–10 秒 | `moon = rise(cursor);` | 游標由方塊變圓球，飛上天，變成月亮 | 上升閃爍音、riser、小鼓滾奏、剪接前 0.1 秒靜音 |
| 10 秒（剪接） | `light(city, moon);` | 全城亮燈、探照燈、LED 外牆跟鼓閃 | 重拍、50 Hz 電網嗡嗡聲同繼電器「咔」一聲 |
| 10–20 秒 | `run(world);` | 一鏡到底：掠過海港 → 穿入兩個字之間嘅峽谷 → 傾側轉彎入大道 | 四拍大鼓、低音、主旋律、按鏡頭經過大廈嘅呼嘯聲 |
| 20–25 秒 | | 急升上天、旋轉俯瞰，全城逐行亮起，原來城市就係段程式碼 | 鼓聲抽走、合唱式和聲、每行亮起一粒鐘聲 |
| 25–27 秒 | `> hello, world` | 城市自己「打」出 `hello, world`，新游標喺尾閃 | 主旋律由小調轉返大調，逐個字母一粒音 |
| 27–30 秒 | | 焦點拉走，標題「你好，世界。」 | D 大調和弦、最後一下游標「嘀」聲 |

主旋律係「hel-lo, world」三粒音（短、短、長）：中段用小調，結尾用大調重現——世界「回應」咗程式。

## 點樣做出嚟（淺白版）

1. **先寫劇本同規則，唔係先畫圖。** 所有嘢都係「時間 → 畫面」嘅數學函數：只要講清楚第幾秒應該見到乜，電腦就可以計出任何一格。咁樣先可以一格格重算、改完再算，亦可以喺你部機即時計。
2. **城市係字砌出嚟嘅。** 手砌一套 5×7 點陣字型；四行程式碼每一點變成一座大廈（678 座），字與字之間變成街道，行與行之間變成大道。b、d、h、l 呢啲有「上伸筆劃」嘅字母做最高嘅大廈，所以海港望過去嘅天際線其實跟住字型高低。外圍再用規則生成兩萬幾格普通城市、山、海港同遠處燈海。
3. **每個像素射一條光線（光線追蹤）。** 畫面上每一點都向城市射一條直線，計佢第一下撞到咩：大廈、地面、海面定天空。撞到大廈就按大廈類型計窗、燈、LED；撞到海面就再射一條反射光線，所以會有天際線倒影同月光喺水面。窗入面甚至用數學「畫」咗間房（視差），近睇會見到深度。
4. **鏡頭語言。** 兩個長鏡頭都用平滑曲線設計：推軌、俯衝、傾側轉彎、急升、旋轉。之後模擬真實電影鏡頭：景深（遠近模糊）、180° 快門動態模糊、變形寬銀幕橫向光暈、泛光、色差、暗角、菲林顆粒同 ACES 調色；畫面比例 2.39:1，好似戲院闊銀幕。
5. **配樂同音效都係計出嚟。** 冇錄音、冇音色庫：振盪器、濾波器、殘響全部係公式，每秒計 48,000 個數字。音樂同畫面用同一個時鐘（96 BPM，一拍啱啱 15 格），所以打字、升起、亮燈、LED 閃爍、字母印出，全部對準。最後做混音同母帶，達到串流平台常用嘅響度（約 −14 LUFS、真峰值 −1 dBTP）。
6. **冇顯示卡都照渲染。** 用嘅雲端電腦冇 GPU，就用瀏覽器入面嘅 CPU 模擬顯示卡（SwiftShader）。每格畫面按需要計 12 至 32 次（每次時間、鏡頭位置同像素位置都有少少唔同），再平均——動態模糊、景深同平滑邊緣就係咁得嚟。全片超過 190 億條主光線。
7. **分層合成。** 畫面（冇字）同字幕／標題層分開渲染，最後先用 FFmpeg 疊埋同混入配樂，好似專業 VFX 咁：改一個字唔使重算幾個鐘（例如片尾字幕嘅可讀性，就係全片渲染完之後先改）。
8. **自己檢查自己。** AI 睇唔到片、聽唔到聲，所以每次改完都會：出低解像度預覽片，抽格砌成「縮圖牆」逐格睇；用程式檢查鏡頭會唔會撞樓、加速度有冇突變；配樂就用響度計、頻譜圖同逐條音軌分析去「睇」聲音。

## 過程中遇到嘅難題

- **CPU 模擬顯示卡會「行晒所有分支」。** 實測發現 SwiftShader 對 `if` 兩邊都會計，連唔需要嘅海面反射都照計。解決：按每段鏡頭編譯專用版本（例如打字段唔包天空同海），打字段快咗 30 倍。
- **光線追蹤迴圈太重。** 改成兩層網格：先用平價步進搵「可能撞到」嘅地段（跳過成片低矮區域），先做精確方塊測試。海港鏡頭快咗接近 6 倍。
- **動態模糊跨越剪接位。** 第 10 秒嗰格曾經出現兩個月亮（快門時間橫跨兩個鏡頭）。改成快門永遠唔跨越剪接點。
- **快速鏡頭嘅模糊出現「階梯」。** 最快嗰段改用 120° 快門（好似動作片），每格 12 次取樣都夠順。
- **字型下載被網絡政策封鎖。** 改由 npm 取得 SIL OFL 開源字型，只抽出用到嘅字元：三個字型合共約 33 KB。
- **AI 聽唔到聲。** 用 BS.1770 響度計、真峰值、頻譜圖、逐條音軌分析同「咔嚓聲」偵測去檢查，並調整咗低頻過重同段落響度。

## 限制同需要人手確認

- 風格化作品，唔係照片級寫實；城市、代碼同地點都係虛構。
- AI 冇「睇」過完整播放、冇「聽」過聲音：畫面靠抽格檢查，聲音靠量度。建議用好啲嘅耳機／喇叭同已校色嘅螢幕睇一次，確認音量平衡同暗部細節。
- 即時運算版每格只計一次，冇動態模糊同景深；舊手機會自動降低解像度，可能仍然偏慢。
- `film.mp4` 係網頁版（約 3 Mbps），為咗檔案細壓縮得比較多；上載 YouTube 等平台請用高碼率版本（約 20 Mbps，檔案較大，冇放入 repo）。

## 點樣重現

需要 Node.js 20+、Playwright（Chromium）同 FFmpeg。

```bash
cd tools/hello-world-film
npm i --no-save playwright            # 或使用 repo 根目錄嘅 devDependency
node render/audio.mjs score.wav        # 約 5 秒
node render/render.mjs --plates --out=plates.mkv          # 全片畫面，CPU 約 3 小時
node render/render.mjs --overlay=overlay                   # 字幕／標題層
FFMPEG=ffmpeg bash render/assemble.sh plates.mkv overlay score.wav film   # 出 film-hq.mp4（約 20 Mbps）同 film-web.mp4（約 12 MB）
```

有 GPU 嘅電腦會快好多。快速預覽：`node render/render.mjs --samples=1 --res=0.5 --preview --out=preview.mp4`。
