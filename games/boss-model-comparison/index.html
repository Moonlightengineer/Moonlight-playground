# 《裂甲守衛》Stage 1：手機單手 3D Boss 戰

你是唯一製作者。在分配給你的獨立目錄內，直接完成以下可玩遊戲，不停在計劃／骨架。這是一次完整輸入，不回問、不等待人手測試、不要求人提供素材或執行命令。未指定的內部實作／美術細節自行決定，不能改動核心操作或省略功能。

## 執行邊界

使用當前模型及已提供工具，不啟動其他模型或子代理、不讀其他參賽組成果。可安裝公開套件；不新增付費服務／帳號，不讀秘密，不動無關檔案，不停止他人服務，不push／部署。不設時間上限，但完成必要檢查後停止，不無限美化。相同阻礙連續三次實質嘗試無進展時記錄限制、繼續可做部分，不重複空轉。工具拒絕時使用合法替代路徑，不繞過安全限制。

## 成品與美術

TypeScript + Vite + Three.js；真3D模型／場景、固定斜俯視鏡頭、地面八方向玩法。古代圓形競技場半徑10m，持劍玩家約1.7m、巨型石甲守衛約3.6m。角色有可辨頭身四肢與武器；有完整待機、走路、出招、受擊、翻滾及死亡動作，可用分件關節動畫。不以無動畫膠囊／方塊作最終角色。

Stylized game taste：石材、金屬、發光裂紋、接地陰影、克制粒子與打擊回饋。玩家冷色、Boss暖色、地面預警橙紅兼具邊界／紋理。自行以程序化幾何或已可用Blender製作；不下載成品角色／素材包，不使用外部生成服務。資產全本機，無runtime CDN依赖。

一個場、一個Boss、單一Boss血條、一種玩家武器。初始玩家在畫面下半部朝Boss，Boss上半部朝玩家。相機不自動旋轉，整個可行走場地保持可見。人物／場邊有碰撞，無接觸傷害。無教學、無操作說明、無常駐提示文字，除錯資訊預設隱藏。只保留遊戲必要HUD、開始、暫停及重試介面。

## 右手單手控制與畫面

直屏優先，右拇指只操作中下方固定圓形區域，毋須第二手指或鍵盤。以扣除safe-area後可用W×H計算：

- 直屏頂部資訊列80px、底部控制面板180px，其間為獨立3D戰鬥視窗。底面板內圓心(0.56W,90)、半徑58px、中心點半徑6px。底座固定不漂移，方向只在圈緣提示。不要預留未實作技能的灰掣。
- 橫屏或H<640：上列64px、右控制面板180px，圓心在右面板內(90,H−86)、半徑48px；左側為戰場。可用H<280時安全暫停並顯示簡短調整視窗訊息。
- 頂部Boss名稱／HP，玩家HP／體力，右上44×44暫停掣，互不重疊。只用必要數字／圖形，無說明段落。開始頁只要遊戲名與開始掣。
- 支援390×844、844×390及360px窄屏，不裁掉場地、控件不貼系統邊緣。camera aspect取戰鬥視窗而非整頁。控制面板不覆蓋地面預警。

## 固定圓手勢（不可換成普通搖桿）

僅在圓內pointer-down開始操作；捕獲後可拖出圈外直到釋放。圈外按下不啟動。滑鼠能重現同一按／拖／放規則，便於本機試玩。

1. 短按≤220ms且位移≤10 CSS px，放手才出普攻；按下不能先出刀。
2. 按住持續拖動，超過10px開始走位。用最近100ms有效手指移動向量，對應畫面八方向，固定4m/s。底座不隨touch移動，不用『離中心偏移量』令角色永遠行。
3. 手指停在8px抖動容差內180ms，角色停步、保留最後面向。容差用穩定區錨點，不能逐event重設。停在圈外亦同樣停步。長按停住只待機，不蓄力、不自動攻擊。
4. 放手前140ms內尾段淨位移≥32px、平均速度≥0.35px/ms、最後有效移動距放手≤80ms，朝尾段方向翻滾。全程按住不翻滾；普通慢拉放手／快拉後停定再放手只停步。
5. 釋放優先：合格快掃嘗試翻滾；否則合格短按且本次未拖動才普攻；其他待機。體力不足的快掃不可變普攻。長按鬆手不補斬。
6. 攻擊鎖定期間不移動；仍收pointer events以支持可取消時段翻滾及有限普攻buffer，不把過期手勢留到稍後執行。
7. pointercancel／失焦／切App／旋轉：清空輸入並暫停，不模擬放手出招；點繼續後需新按下。控制區禁原生滑動／縮放，UI按鈕不觸發戰鬥。

## 玩家戰鬥

HP100、體力100、碰撞半徑0.35m；方向只由移動／翻滾改變，不自動朝Boss。受傷後0.65s無敵、短受擊反應；取消普攻前搖，已開始判定／後搖不因受擊解除鎖定但仍扣血。死亡立即優先。

三段點按連擊：傷害18／22／32；前搖／命中窗口／後搖分別(0.12,0.10,0.20)、(0.14,0.10,0.23)、(0.23,0.12,0.35)秒。面前扇形半徑1.8／1.9／2.2m，角度100／110／70度。每子攻擊對Boss只命中一次，落空不扣血；動畫與時機相符。上一段完成後0.65s內點按接下一段；只保留一個0.18s普攻buffer。超時、受擊或翻滾重設連段。

翻滾耗35體力、距離2.4m、歷時0.42s；開始後0.06–0.32s無敵，結束0.12s恢復。最後翻滾0.8s後體力30/s回復。可取消待機、移動或普攻後搖；不可取消普攻前搖／判定，不排隊。不得穿Boss或場邊；無敵外受擊中止翻滾。以殘影／動作表示，不靠文字解說。

## Boss：追人＋兩招

Boss HP900、碰撞半徑1.1m、追蹤速度1.6m/s。只在中立／追蹤時朝向玩家。距離≤3.5m且上一招冷卻完成才出招；交替橫掃→重砸。招後有後搖再加0.60s中立時間，給反擊機會；距離太遠就繼續追蹤，不原地連放招。Boss不能與玩家重疊或推穿牆。

- 橫掃：舉起大武器，前方110度／半徑4m扇形提示，前搖開始即鎖方向；0.90s前搖、0.16s判定、0.85s後搖，22傷害。
- 重砸：武器高舉，前搖开始锁定玩家当时位置，半徑2.4m圓提示；1.20s前搖、0.18s判定、1.10s後搖，32傷害。武器／能量落點必須對準提示位置，不允許地面一處發光而另一處扣血。
- 提示由淡到實，active開始閃一下、結束消失；顯示與hit region共用同一幾何。傷害判定用玩家碰撞圓相交，同招最多一次；不在判定前扣血、不最後瞬間追蹤。

## 基本系統

開始→短開場→戰鬥→勝利／死亡→重試。結算只顯示結果、用時、重試。雙方同一步致死判玩家失敗。重試重置HP／體力／AI／timer／pointer／特效／連段，Boss回完整初始狀態。暫停與背景不跑CD、傷害、AI、時間；回來不補跑。模擬採受控步長避免卡頓穿透。

揮劍、命中、翻滾、Boss攻擊、勝負有简洁音效，可程序化生成；首次操作後啟動audio，提供靜音。輕微閃光／小震屏不遮預警。無登入／後端／存檔要求，無PWA、蓄力、技能、額外Boss階段；不要提前增加這些功能。

## 自主修正循環與必要檢查

自行安裝／build／啟動 → 用已有瀏覽器工具實際開頁與操作 → 列出失敗 → 修正 → 重測受影響項。優先啟動、手勢、戰鬥、流程、佈局，再外觀；不可要求追加prompt才修。只做必要檢查，不建立大型測試體系。

檢查五組：
1. build與實際頁面可啟動；直／橫屏可見、沒有阻塞錯誤。
2. 點按三連、拖拉八向、停指停步、掃放翻滾、慢放不誤觸、圓外按下無作用。
3. 命中／落空、體力、無敵、後搖與一次命中規則。
4. Boss追人、兩招預警與判定、收招空隙，無永久卡住。
5. 勝負／重試／暫停可以操作且乾淨重置。

可用隱藏development診斷及临时HP設定檢查勝負，但交付預設關閉作弊，至少操作一次正常戰鬥。不能以HTTP200或build代替畫面／互動驗證。工具無法驗的項目列未驗，不偽造通過；合法替代測試可做，但不聲稱真機。完成五組後停止，不自行追加範圍。

## 交付與強制停止點

交source、lockfile、本機資產、README啟動命令、實際可玩URL、五組檢查結果及已知限制；保留server供玩。完成後立刻停止實作，不自動續做。

# 《裂甲守衛》Stage 2：戰鬥深化與畫面完成度

只有Ken完成第一階段試玩並明確選擇繼續後，總控才會送出此輸入。收到後在分配給你的第一階段副本接續，保留原版不修改。先讀取現有程式，保留古代競技場、持劍玩家與石甲守衛的題材、右手固定圓手勢與基本戰鬥；可重製模型、材質、光影、動畫及鏡頭構圖，不必保留第一階段的粗略美術。不要重寫成別種遊戲。使用當前模型，不回問、不用其他模型／子代理、不新增付費服務／外部資產、不push／部署。

本階段無時間上限；自行實作、啟動、操作、修正直至以下必要功能可用。相同阻礙三次實質嘗試無進展則保存限制，不無限空轉。沒有人工追加提示，不要求使用者先測試。未指定細節保留原有設計。

## 畫面目標：可直接試玩的完整風格化3D遊戲

畫面提升與新增戰鬥功能同樣屬於本階段交付。目標是有一致美術方向、清楚角色輪廓、可信重量及克制特效的手機Boss戰。美術成果必須出現在實際遊玩鏡頭，不用獨立展示頁或放大特寫代替遊戲內效果。自行定下統一造型語言後貫徹，避免每件物件各用一種風格。

### 鏡頭與視覺主次

- 保留固定斜俯視角與畫面八方向對應；不自動旋轉，不用電影運鏡干擾輸入。**本階段可取代第一階段「全場永遠入鏡」限制**：允許平滑跟隨及有限縮放，以玩家、Boss、當前危險範圍為構圖主體。相機不得突然跳動或每次出招抽動。
- 390px直屏、一般近戰距離時，玩家投影高度以約48–64 CSS px、Boss約90–130px為構圖目標，按實際戰鬥視窗調整，並非硬性像素驗收。拉遠時優先保留双方及逃生方向；不要為追求大模型裁掉腳下預警。場邊接近時讓邊界可見，Boss即將出招時其身體和相關預警須在畫面內。
- 第一眼看清玩家位置與面向，第二眼看清Boss動作與危險範圍，再看環境。不要靠滿屏高亮、巨大HUD或常駐箭嘴補救構圖。控制面板仍與戰場分離，既定單手按鈕位置不變。

### 模型、材質與場景

- 玩家有明確頭盔／面部區、肩甲、軀幹、手臂、腿及持劍輪廓；用比例、層次、切面和少量不對稱設計形成辨識度。Boss有獨特肩背剪影、分層石甲、關節空隙、核心與一眼可辨的大武器。程序化幾何可用，但不能只把同形方塊堆成人形便當完成。
- 模型細節以正常手機視角仍可辨的主形為先，輪廓與關節動作優先於微小裝飾。裝甲與身體有視覺分層，持劍／握錘與手部位置一致；避免肢體長期互穿、武器漂浮、腳底離地。
- 石材、金屬、布料、發光核心須有可辨的明暗、粗糙度及色彩差異。用程序化紋理、頂點色或局部磨損表現材質；不能全場只靠純色加emissive。亮面要有層次，不要把金屬全做成塑膠。
- 競技場有清楚可行走地面、低干擾鋪面紋理、邊界與少量有節奏的環境物件。裝飾只在周邊建立深度及場景氣氛，不遮玩家、Boss或預警；不得為美術新增碰撞障礙。避免把可走地面壓成全黑。
- 使用有方向的主光、適量環境補光、接地陰影及必要輪廓光分開角色與背景。玩家冷色、Boss暖色、危險區橙紅的語言一致；P2紫紅核心也要與傷害範圍區分。控制曝光和bloom，發光處仍有形狀，不可整片白色。

### 動作、打擊及特效

- 待機有呼吸／重心，走路有腳步交替、身體跟進；三段普攻有不同起手、劍路與收招，不能只改特效顏色。翻滾要看得到身體翻轉、位移與落地恢復，不是站立滑行。
- 兩段蓄力在姿勢、劍光形狀、粒子運動與釋放動作上均有區別。Boss舉武器時有重心預備，出手時軀幹跟進，落點和後搖有重量；P2變化要能從石甲結構、核心及站姿辨認，不能只換HP條顏色。
- 前搖、active、後搖各有可讀的動作節奏，與本文既定數值及判定同步。用劍弧、命中閃光、少量碎屑、局部衝擊環和聲音建立打擊感；命中特效只在真命中時發生，落空不能播放同樣的命中回饋。可做輕微視覺震動，但不改模擬時間或遮住下一次預警。
- 招式特效靠形狀、範圍與節奏區分，不只靠顏色。所有地面危險區有清楚外緣、填充層次及由前搖到爆發的進度感；預警必須貼地、不閃爍、不被粒子或角色光暈蓋過。效果消退乾淨，不殘留成另一個假危險區。

### HUD與手機效能

- HUD像遊戲介面：統一字體層級、邊框、圖示、血條與CD視覺；Boss血條、玩家狀態、兩格蓄力及三技能保持清楚而簡潔。保留必要短名與數字，不增加教學、说明段落、設定大廳或展示面板。
- 在現有Three.js架構內選擇有效且可維護的做法；重複環境物件可共用幾何／材質或instancing，限制即時陰影、粒子與透明層成本，合理限制pixel ratio。資產仍全部本機，不新增成品素材包、外部生成服務或runtime CDN。不要為增加細節而令手機操作明顯卡頓。
- 若需要降低畫質，先減少背景装飾、粒子量、bloom與陰影成本，保留角色輪廓、動作、預警和輸入反應。只陳述實際觀察到的效能，不承諾未實測裝置達到指定FPS。

## 追加操作與兩段蓄力

保留點按普攻、持續拖拉走位、快掃放手翻滾。停指8px容差內180ms後停步並開始蓄力，面向鎖定；0.65s第一段、1.50s第二段，計時從停指成立後起算。滿蓄維持不自動出招；重新拖動取消；放手出當前段。未滿第一段的長按釋放不攻擊。放手仍優先判定快掃翻滾。

- 第一段：琥珀劍光、壓低身體，65傷害，面前半徑2.5m／100度；前搖0.20／判定0.12／後搖0.45秒。
- 第二段：藍白聚光、雙光環、舉劍，125傷害，面前寬2.4m／長5m裂地帶；前搖0.35／判定0.15／後搖0.80秒。
- 每招只命中一次，動畫与实际方向／判定一致。受擊取消蓄力。翻滾可取消蓄力及重擊前搖，不能取消重擊判定／後搖。滿蓄提示只播放一次；不自動瞄準。

## 三技能與單手布局

直屏上列104px、底控制面板232px，圓心(0.52W,142)、半徑58。技能直徑56，相對圓心：突刺(−46,−100)、旋風(+46,−100)、治療(+105,−18)。橫屏上列72px、右面板220px，圓心(94,H−86)、半徑48，技能相對(−38,−88)、(+38,−88)、(+91,−8)。W/H扣safe-area。控制面板不覆蓋戰場，三掣不重疊，保留固定底座。

用右拇指先放開手勢再按技能即可；不要求兩指同時按。由手勢區拖到按鈕放手不能觸發技能。技能要獨立pointer-down／up，移出按鈕取消。成功施放取消蓄力／連段；原手指之後放手不補斬。無效技能不取消原狀態。按鈕顯示圖示／短名／CD暗罩與向上取整秒數。上方加兩格蓄力資訊，不增加教學或說明文字。

| 技能 | 效果 | CD與動作 |
|---|---|---|
| 破風突刺 | 沿當前面向前進最多3m，寬1m，55傷害，受碰撞阻擋 | CD8s；前搖0.15s，總鎖定0.50s |
| 旋風斬 | 自身半徑2.8m，75傷害，一次命中 | CD12s；前搖0.20／判定0.15／後搖0.40s |

技能只在待機／移動／蓄力施放，不buffer、不自動朝Boss。開始即耗CD，受擊中斷前搖時不退CD、不出效果。技能鎖定不能翻滾取消。暫停停止CD，重試清零。

## Boss 三條血與兩階段

總HP1800，每條600，顯示當前條與×3／×2／×1；溢出傷害跨條不能吞掉。HP≤900一次性進P2，當前整招及後搖結束才轉，致死直接死亡。

變身1.8s：雙方不能出招、無敵，CD／體力暫停；石甲明顯裂開／移位，核心紫紅。結束1s安全時間後才前搖。先保留P1兩招，P2擴充：

- 橫掃在第一擊後0.60s反手追擊，另有新扇形預警與方向鎖定，22傷害。
- 重砸在原判定後0.70s追加半徑2.4–4m外環，24傷害；另畫環形預警，內圈安全。
- 破陣衝撞：P2新增，寬2.2m、最長8m鎖線預警，前搖1.10／衝撞0.55／後搖1.00s，28傷害；碰場邊／玩家停下，不推穿牆。
- 核心震波：1.30s預警，以Boss為心，半徑1.5m起、寬0.8m環以3m/s擴至8.5m，26傷害，後搖1.20s；環內外安全，可翻滾穿過。

P1仍交替橫掃／重砸；P2循環雙橫掃→震波→衝撞→重砸外環。追擊完成才算整招；每招後保留0.60s中立。近戰前需追到距離，追蹤最多3s仍太遠可跳下一招，避免卡住。每個子攻擊一次判傷，所有提示與hit geometry一致。

## PWA及回歸

追加manifest、icon、service worker，核心資產全本機；首次快取完成後可離線開局／重試。只要求localhost可行檢查，不要求部署、實機安裝、錄影、效能證書。保留簡潔遊戲介面、靜音、勝負重試、背景暫停及乾淨狀態重置，不添加設定大廳或教學。

自主循環：build→開頁→試玩→列失敗→修正→重測。必要檢查：原手勢／普攻不倒退；兩段蓄力的方向／取消／後搖；三技能效果／CD；P2門檻、動畫及各招；勝負／重試／暫停；直橫屏布局；本機PWA。畫面檢查合併在同一輪試玩：實際查看正常戰鬥、二段蓄力及P2出招畫面，確認角色／動作可辨、危險區可讀、特效不遮操作，發現問題自行修正；不用另建美術測試系統、錄影或提交大量截圖。工具不支援的操作列未驗，不假報完成；不得用刪功能方式過測。

交付source、啟動URL、檢查結果與限制，保留server。完成後停止，等待Ken最終試玩，不修改封存的第一階段成果。

04 / METHOD & NOTES

如何測試，以及如何解讀。

題目、工具與人工介入

同一題材：古代圓形競技場、持劍玩家與石甲 Boss。Stage 1 包含移動、翻滾、三連普攻、追擊、橫掃及重砸；Stage 2 加入蓄力、三招技能、多條血量、第二階段、PWA，以及更強的 3D 畫面要求。

各組在獨立對話及目錄執行。Astra／Sol 使用 Codex High；Opus 使用 Devin，Stage 2 因額度及執行中斷，改由 Claude Code Opus 5.5 High 接續。總控處理工具批准與執行恢復，不追加遊戲設計提示、不代改遊戲邏輯。因此是單份 prompt 配合自主修正，並非完全零人工介入，也不是完全相同工具環境的受控 benchmark。

部署僅作資源路徑及 PWA 子目錄包裝，原始與部署產物分別封存。原規格要求遊戲內不設教學，因此不把缺少教學視為未完成規格。

價格、發布背景與結論範圍

GPT-6 Sol 與 Opus 5.5 於 2026 年 9 月 22 日發布；GPT-6 Astra 較早於 9 月 3 日發布。Anthropic 提及外部測試者比較多款 Claude 的單 prompt 遊戲，Opus 5.5 的畫面與完成度獲較高評價；這不是官方與 GPT-6 的 3D 對照測試。

截至本次核對，Sol 標準 API 每百萬輸入／輸出 tokens 為 US$2／US$10（提示長度至 272K），Opus 5.5 為 US$4／US$20。這兩項單價是其一半；快取、總用量及訂閱另計，不能推論實際任務成本也減半。

每模型只有一組作品，結論反映本次成品與個人試玩感受。文字到 3D 遊戲的生成表現，不等於已獨立測量圖像輸入理解能力。工具等待、額度中斷及總控用量不能當作模型推理速度或成本。
